Object-Oriented Programming

Module record for object-oriented software design in Python, including classes, inheritance, polymorphism, encapsulation, abstraction, design patterns and testing.

Module Overview

This module developed my understanding of object-oriented programming and how software can be structured using interacting classes and objects. Building on procedural Python, I explored inheritance, polymorphism, encapsulation and abstraction alongside exception handling and software design patterns.

The module also introduced professional software development practices including modularisation, version control, code review, unit testing and debugging. These concepts were applied through an Online Shopping System and a final practical test.

Learning Outcomes

  • Demonstrate a thorough understanding of object-oriented programming principles and concepts.
  • Understand existing software systems to identify opportunities for refactoring and improvement using object-oriented methodologies.
  • Design and implement object-oriented software solutions using appropriate design patterns and programming techniques.
  • Apply object-oriented design principles to model real-world problems and develop basic software applications.

Development Across the Module

The nine units progressed from fundamental OOP concepts to software design patterns, professional development practices and software testing.

  • Unit 1: Procedural and object-oriented programming, classes, objects and core OOP principles.
  • Unit 2: Classes, objects, constructors, destructors, class methods and instance variables.
  • Unit 3: Inheritance, method overriding, polymorphism, abstract classes and interfaces.
  • Unit 4: Encapsulation, abstraction, access modifiers, data hiding and abstract data types.
  • Unit 5: Exception handling, exception propagation and custom exceptions.
  • Unit 6: Creational, structural and behavioural design patterns, including Singleton, Factory, Adapter, Decorator, Observer and Strategy.
  • Unit 7: SOLID principles, modularisation, version control and collaborative development.
  • Unit 8: Practical OOP projects, code review, peer evaluation and application of software design principles.
  • Unit 9: Unit testing, Test-Driven Development, debugging, edge cases and boundary conditions.

Mid-Module Assessment: Online Shopping System

The mid-module assessment was an individual presentation designing an Online Shopping System in Python. I used Product, Customer, PremiumCustomer, Order and User classes to demonstrate object-oriented software design.

  • Due date: 29 June 2026
  • Weighting: 30%
  • Grade: 70%
  • Key concepts: classes and objects, inheritance, polymorphism, encapsulation, abstraction and interfaces

The design used UML diagrams, Python code and program outputs to demonstrate how products, customers and orders could be represented as interacting objects. PremiumCustomer extended Customer with discount behaviour, while an abstract User class and Orderable interface demonstrated abstraction.

Mid-Module Feedback

Feedback recognised a good understanding of the main OOP concepts, clear evaluation and effective use of UML diagrams and code examples. The presentation also successfully considered the strengths, limitations and future development of the system.

To improve, I needed to demonstrate the complete application workflow more clearly through a dry run, develop some class relationships further and connect academic sources more directly to design decisions. A Store Manager class and clearer premium membership attributes were also suggested.

End-of-Module Assessment: Individual Test

The end-of-module assessment was a two-hour individual test containing seven questions. It applied the later module concepts through practical and theoretical tasks involving design patterns, modularisation, version control, class design, code review and automated testing.

  • Completed: 1 August 2026
  • Duration: 2 hours
  • Weighting: 70%
  • Grade: 66%
  • Design patterns: Singleton and Observer
  • Software development: modularisation, Git workflows and code review
  • Implementation: validated Task class and unit tests

Assessment Work

I implemented a Singleton PluginManager using __new__() and an initialisation guard, and applied the Observer pattern using plugins that reported status changes to a manager. I also designed a validated Task class and created unit tests for initialisation, assignment and status changes.

The test also explored modular code organisation, feature-branch workflows and the role of code reviews in defect detection, consistency, knowledge sharing and maintainability.

End-of-Module Feedback

Feedback recognised correct implementations of the Singleton and Observer patterns, clear modular organisation, a logical Git workflow, a validated Task class and relevant unit tests.

The main area for improvement was providing fuller dry runs and exact expected outputs. Further improvements included stronger constructor validation and more detailed discussion of coding standards, remote teamwork and collaborative review processes.

Reflection

This module changed how I approach programming. Rather than focusing only on whether individual functions work, I became more aware of where responsibilities should belong, how objects should interact and how software can remain maintainable as requirements change.

The Online Shopping System showed me that using classes alone does not automatically create a strong object-oriented design. Relationships between classes need to be considered carefully, and the feedback highlighted the importance of demonstrating complete workflows rather than isolated examples.

The later units also broadened my understanding of software engineering. Design patterns, modularisation, version control, code review and testing showed how code quality depends on both software design and the development process used to maintain it.
